# Aedifico Web Studio: aedifico.studio

Portfolio and lead-generation site for the web design / local SEO business.
23 static pages generated by a small Node script. No framework, no dependencies.

Live at **https://aedifico.studio** (GitHub Pages, custom domain, HTTPS enforced).

## How this repo works

The HTML in the repo root is **generated output**. Do not edit it by hand: the next build
overwrites it. Edit the sources in `build/` instead, then run the build.

```
build.js              orchestrator: renders pages, writes sitemap.xml + robots.txt
build/site.js         domain, brand, nav, email, areas served, form endpoint
build/data.js         all content data: projects, services, areas, guides
build/layout.js       page shell: head, meta, JSON-LD, nav, breadcrumbs, footer
build/blocks.js       reusable sections: page head, cards, FAQ, CTA, form, prose
build/pages/*.js      one module per page group

styles.css            all styling, hand-written
script.js             sticky nav, mobile menu, scroll reveal, hero glow
assets/work/*.jpg     case-study screenshots
assets/og.jpg         social share card
tools/og.html         generator for the share card
CNAME                 aedifico.studio
```

Build and deploy in one step:

```sh
./deploy.sh "what you changed"
```

That runs `node build.js`, commits, pulls, and pushes. To build without deploying, run
`node build.js` on its own and open `index.html`, or serve the folder so clean URLs resolve
the way GitHub Pages resolves them.

## Adding content

**A new guide** is two edits: append an entry to `guides` in `build/data.js`, then add the
article HTML under the matching slug key in `bodies` in `build/pages/guides.js`. The hub
page, sitemap, JSON-LD, and cross-links all pick it up automatically.

**A new case study**: append to `projects` in `build/data.js` and drop a screenshot in
`assets/work/`. Capture with headless Chrome, then resample:

```sh
"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --headless --disable-gpu \
  --hide-scrollbars --screenshot=out.png --window-size=1440,3400 \
  --virtual-time-budget=12000 "https://example.com/"
sips -s format jpeg -s formatOptions 68 --resampleWidth 900 out.png --out assets/work/x.jpg
```

Set `tall: true` for a full-page capture, `false` for a single viewport. A site whose hero
uses `100vh` will stretch to fill a tall window, so capture those at `1440,1000` instead.

**A new market**: append to `areas` in `build/data.js`. Give it a genuinely specific `intro`
and an honest `localNote`. See the warning below.

## SEO decisions worth knowing

- **One H1 per page**, unique title and meta description on all 23. Titles are capped at 60
  characters by `title()` in `build/layout.js`, which appends the brand suffix only when it
  fits. Descriptions are trimmed at a word boundary by `desc()`.
- **JSON-LD** on every page: a `ProfessionalService` node plus per-page `Service`,
  `CreativeWork`, `BlogPosting`, `FAQPage`, and `BreadcrumbList` as appropriate.
- **Breadcrumbs** are visible and mirrored in schema.
- **`sitemap.xml` and `robots.txt` are generated**, never edited by hand. The 404 page is
  excluded via `noindex: true`.
- **Clean URLs**: every page is `path/index.html`, so no `.html` appears in a URL.

### The address problem

There is **no street address and no phone number** in the schema, because none is published.
This is deliberate: inventing one would be worse than omitting it.

The consequence is real. `LocalBusiness` rich results and map-pack ranking need a verified
Google Business Profile with an address or a defined service area. **This site cannot rank in
the map pack until that profile exists.** Everything here targets the organic results below
the map pack, which is a different and slower game. Setting up the profile is the highest-value
thing left, and it is free.

### The location pages

`/areas/*` pages carry a thin-content risk. Google penalises doorway pages: near-identical
pages differing only by a city name. These avoid that by having genuinely different content
per market: real builds where they exist, city-specific intros, and a plain admission where
there is no local work yet.

**Keep it that way.** If you add a market, do not copy an existing page and swap the city.
The Appleton page says outright that there is no Wisconsin build yet, and that honesty is
what makes it a real page instead of a doorway.

## Before this goes further

- [ ] **Form endpoint**: `formAction` in `build/site.js` is still
      `https://formspree.io/f/YOUR_FORM_ID`. Until you paste a real ID, **every submission
      silently goes nowhere** and the visitor sees no error. This is the most urgent item.
- [ ] **Google Business Profile**: see above. Nothing on this site substitutes for it.
- [ ] **Search Console**: verify the domain and submit `https://aedifico.studio/sitemap.xml`.
      The site sells doing this on launch day for clients.
- [ ] **Per-page share images**: every page currently shares `assets/og.jpg` except case
      studies, which use their screenshot. Fine for now.

## Copy rules

Prose here is written to avoid the usual AI tells, and edits should hold the line:

- **No em dashes anywhere**, including alt text and meta. `grep -c '' build/**/*.js` stays 0.
- No "not X, it's Y" contrasts, no three-item negative lists.
- Active voice with a human subject. "I submit the sitemap," not "the sitemap is submitted."
- Cut adverbs.

## What the work section claims

The four local builds are **concept builds**. Real businesses, real research, real code, but
none of them is that business's live website. The work hub and every case study say so.
Do not soften that into language implying they are adopted clients.

`aedifico.io` is built on Lovable, not hand-coded. Its case study is credited for
positioning, copy, and art direction only, and the page discloses the platform. A hand-coded
rebuild removes the contradiction with the "no page builder" pitch.
